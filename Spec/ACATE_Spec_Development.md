## §1 包与修改

[返回顶部](#toc)

<a id="s1-1"></a>
### §1.1 包的组成

[返回顶部](#toc)

- 工具包只包含下列文件：
  - `README.md` 和 `LICENSE`；
  - `Spec/` 下的规范文档与迭代记录；
  - `Script/` 下的三个工具；
  - `Template/` 下的固定模板、示例图和示例图的输入；
  - `Compare/` 下的对比图；
  - `Test/` 下的测试；
  - 仓库设置 `.gitattributes`、`.gitignore` 与 `.github/workflows/ACATE_Test.yml`。

<a id="s1-2"></a>
### §1.2 修改的做法

[返回顶部](#toc)

- 先收齐一组相关决定，列全影响面，再一次实施。
- 规范、工具、示例和测试一起修改。

## §2 规范的写法

[返回顶部](#toc)

<a id="s2-1"></a>
### §2.1 文档结构

[返回顶部](#toc)

- 每份文档的第一行是一级标题，与文件名相同；一级标题下面写加粗的中文副标题。
- 章编号写 `§1`，节编号写 `§1.1`；每个章、节标题前放锚点，标题下面放返回顶部。
- 副标题下面先用一句话说本文管什么，再放目录。
- 正文一行一句；并列的条件和做法拆成子项，一项一行。
- 每节先写全部规则，节末再写例子。

<a id="s2-2"></a>
### §2.2 写法

[返回顶部](#toc)

- 用正常、得体、简洁、准确的书面语，以肯定句写明做什么。
- 一件事只说一次。
- 规范之间的互相指向一律写成引用。
- 例子一律用编造的行程和公开的地名，不写真实的行程和个人信息。
- 一侧是中文的标点用全角；两侧都是英文或数字的用半角。
- 引号用「」。

<a id="s3"></a>
## §3 测试与发布

[返回顶部](#toc)

<a id="s3-1"></a>
### §3.1 测试

[返回顶部](#toc)

- 完整回归：`python -B -X utf8 -m unittest discover -s Test -p "ACATE_Test_*.py"`，再运行 `node --test Test/ACATE_Test_Workbook.mjs`。
- 推送到 GitHub 后，`ACATE_Test.yml` 在 Windows、macOS、Linux 上各跑一遍完整回归。
- 测试只用生成的样本，不放真实的照片。

<a id="s3-2"></a>
### §3.2 发布

[返回顶部](#toc)

- 打了 `vX.Y.Z` 标签的提交即该版本的发布内容。
- 打标签前跑完整回归，并核查全包没有真实行程和个人信息。
